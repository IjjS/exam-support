# exam-support

[English README](README.md)

**아직 풀어보지 않은 토픽**과 **풀어봤지만 취약한 토픽**을 찾기 위한 마크다운 기반 자격증 학습 시스템입니다. 시험 범위를 토픽으로 나누고, 토픽별 출제 범위와 성적을 기록해 학습할 곳을 찾습니다.

8개 에이전트 스킬과 로컬 마크다운 파일로 작동합니다. 데이터베이스나 서버는 없습니다. 휴대전화에서 짧은 출력과 한 줄 답변으로 사용할 수 있게 설계했습니다.

## 학습 공백을 찾는 방법

| 신호 | 알 수 있는 것 | 다음 학습 |
|---|---|---|
| 한 번도 풀지 않은 토픽 | 아직 접하지 못한 시험 범위 | 진단 퀴즈 |
| 오답·찍어서 맞힘·애매하게 맞힘 | 다시 확인해야 할 지식 | 약점 퀴즈와 오답노트 |
| 오답 유형 | 지식 부족, 개념 혼동, 문제 오독, 매력적인 오답, 암기 누락 중 무엇이 문제인지 | 개념 노트, 비교표, 집중 연습 |

커버리지와 정답률은 서로 다른 정보를 보여줍니다. 한 번도 풀지 않은 토픽은 **미확인 영역**이지 약점으로 판정된 영역이 아닙니다. 상태 화면은 표면 정답률과 실질 정답률을 함께 보여줍니다. 찍어서 맞힌 답은 실질 정답률에서 제외합니다.

## 시작하기

1. 시험 가이드, 학습 자료, 기출문제를 [`_inbox/`](_inbox/README_KO.md)에 넣습니다. 등록할 때 파일 경로, URL, 첨부 파일로 전달해도 됩니다.
2. `/exam-init {시험명}`으로 시험을 등록합니다. 토픽 지도와 문제 형식이 만들어집니다. 기출문제가 있으면 문제은행에 저장하고 토픽과 형식을 실제 문항에 맞춥니다.
3. `/exam-quiz`로 미확인 토픽을 풉니다. `/exam-status`로 커버리지, 약점 토픽, 다음 추천 작업을 확인합니다.
4. `/exam-harvest 3`으로 큐에 쌓인 토픽의 근거 있는 노트를 만듭니다. 이미 확인된 약점을 다시 풀고 싶다면 약점 모드를 요청합니다.

기본 퀴즈는 언제나 진단 모드입니다. **약점 모드는 요청할 때만** 실행되며, 진단 또는 모의고사 세션을 3회 이상 마쳐야 사용할 수 있습니다. 기출 문제은행이 있다면 소스 모드에서 기출을 순서대로 풉니다.

```text
/exam-quiz             # 풀지 않은 토픽 찾기
/exam-quiz 약점모드     # 기록된 약점 다시 풀기
/exam-quiz 소스모드 20  # 기출 20문항 순서대로 풀기
```

## 답은 한 줄로

```text
1 3? 2,4?? 5
```

각 항목은 문항 순서에 대응합니다. 쉼표로 복수 선택지를 적고, 확신이 없으면 `?`, 찍었으면 `??`를 붙입니다.

| 답변 | 맞혔을 때 채점 | 복습 기록 |
|---|---|---|
| `2` | 정답 | 기록하지 않음 |
| `2?` | 정답 | 애매한 답으로 기록; 확신한 정답 2회 연속 후 해소 |
| `2??` | 오답 | 찍어서 맞힌 답으로 기록; 확신한 정답 3회 연속 후 해소 |
| 실제 오답 | 오답 | 오답으로 기록; 확신한 정답 3회 연속 후 해소 |

`?` 또는 `??`를 붙이면 연속 확신 정답 횟수가 초기화됩니다. 채점 후에는 모든 문항의 모든 선택지에 한 줄씩 판정을 제공합니다.

## 스킬

| 스킬 | 용도 |
|---|---|
| `/exam-init` | 시험 등록; `--bank`로 기출 추가, `--refine`으로 토픽 수정, `--format`으로 문제 형식 갱신 |
| `/exam-quiz` | 기본 진단 퀴즈; 필요할 때 약점·소스·영역·모의고사 모드 요청 |
| `/exam-status` | 커버리지, 정답률, 약점 토픽, 다음 작업 확인 |
| `/exam-harvest` | 큐에 쌓인 토픽의 개념 노트 작성·확장 |
| `/exam-comp` | 헷갈리는 개념 비교 |
| `/exam-desc` | 시험 개념 설명 또는 이름을 지정한 과거 문항 조회 |
| `/exam-reset` | 백업과 확인 후 학습 기록 초기화 |
| `/exam-skills` | 스킬과 사용법 목록 확인 |

새로 만드는 문제는 시험별 `format.md`를 따릅니다. 진단 모드에서는 미확인 토픽을, 약점 모드에서는 기록된 취약 토픽을 우선합니다. 소스 모드는 저장된 기출문제를 문제은행 순서로 보여줍니다. 기출 정답에 이견이 있으면 노트와 공식 자료로 검증하고, 복수 정답이 가능하거나 문항에 결함이 있으면 채점에서 제외합니다.

## 자료와 기록

자료를 찾을 때 시험의 `_sources/`를 먼저 확인한 뒤 웹을 검색합니다. 주장과 정답을 가르는 근거는 공식 문서나 가이드로 검증합니다. 공식 근거가 없는 경우에도 읽을 수 있는 사용자 제공 파일은 자체 근거가 될 수 있습니다. 검증할 수 없는 문제에는 `[UNVERIFIED]`를 표시하고 관련 토픽을 노트 작성 큐에 넣을 수 있습니다. 노트에는 출처와 날짜를 기록합니다.

URL, PDF, Markdown, TXT, DOCX, XLSX, PPTX, PNG, JPG를 받을 수 있습니다. HWP는 먼저 PDF로 내보내야 합니다. `_inbox/` 파일은 시험별 `_sources/`로 복사하며 원본은 남깁니다.

```text
exams/{slug}/
├── exam.md              시험 정보와 날짜
├── blueprint.md         영역, 비중, 영구 토픽 ID
├── format.md            시험별 문제 형식
├── _sources/            제공 자료와 선택적인 기출 문제은행
├── notes/               토픽 노트, 비교표, 사실 카드
└── state/
    ├── mastery.md       토픽별 풀이, 커버리지, 정답률, 약점 점수
    ├── wrongbook.md     오답, 찍어서 맞힘, 애매하게 맞힘
    ├── sessions.md      세션 요약과 소스 모드 진행 위치
    ├── harvest-queue.md 노트 작성 대기 토픽
    └── log/             지난 문제와 채점 결과
```

시험별 학습 데이터는 서로 분리됩니다. `blueprint.md`는 시험 범위를 정의하고, 변화하는 숙련도와 커버리지는 `state/mastery.md`에 기록됩니다. 시험 영역이 개편되어도 토픽 ID는 유지합니다. 일반 퀴즈 세션은 누적되는 문제 로그를 다시 읽지 않습니다.
